## [Unreleased]

### Added

- **Admin accounts and roles (`cloudflare/worker.js`, `cloudflare/admin.html`, `cloudflare/schema.sql`, `docs/admin.md`)**: the admin page now signs in with `POST /api/admin/login` and gets a 30-minute admin token (`as_…`, stored hashed in a new `admin_sessions` table) that the page keeps in memory only; the old `sessionStorage` copy of the secret is removed and cleared. Sign-in is either an admin account (name + password, PBKDF2, new `admins` table) or an `ADMIN_SECRET` password, which counts as role 「全部」 and is meant for creating the first accounts; `tools/econ-admin.mjs` keeps sending the secret directly. Four roles: 只能看 (read only), 经济 (ink, items, gifts, codes, economy values, restores), 封禁和账号 (bans, pardons, player passwords except Dev), 全部 (also flags, admin accounts and the Dev account). Every route is checked on the server; a route a role cannot use answers 403 and the page only shows the message, while an expired or revoked admin token answers 401 and the page asks to sign in again. A new 「管理员」 tab (role 全部 only) creates admins, changes role or password, and disables or re-enables them; changing the password or disabling signs that admin out at once, and nobody can disable or demote themselves. `POST /api/admin/logout` ends the admin token. Every admin sign-in (`adm_login`) and account change (`adm_acct`, never the password) goes into `econ_log` and shows in 「操作记录」. The 20-failures-per-IP lock covers the sign-in too. **Needs a Worker redeploy.**
- **Turnstile check on sign-up and repeated failed sign-ins (`cloudflare/worker.js`, `src/cloud.js`, `docs/admin.md`)**: when the Worker has both `TURNSTILE_SITEKEY` and `TURNSTILE_SECRET` and the `auth.turnstile` flag is on, registration needs a Cloudflare Turnstile check, and so does sign-in after 3 wrong passwords for a name or 10 from an IP within 15 minutes. Without the check the server answers 400 with `need: 'turnstile'` (not counted against the hourly registration limit); the page shows the check in a small dialog, loading Cloudflare's script only then, and resends the request with the result. Cancelling shows the server's message and never falls back to a local account. If Cloudflare's verify endpoint cannot be reached the check counts as failed. Without both settings everything works as before. The site key reaches the page through `GET /api/flags`. **Needs a Worker redeploy;** setup steps in `docs/admin.md`.
- **Sign-in log (`cloudflare/worker.js`, `cloudflare/admin.html`, `cloudflare/schema.sql`, `docs/admin.md`)**: a new `auth_log` table records registrations, sign-ins, failed sign-ins (wrong password, no such account, locked out), sign-outs, signing out other devices, reuse of a retired refresh token and admin password resets, kept for 90 days. The IP is stored only as the first 16 hex characters of an HMAC (key from the optional Worker variable `LOG_SALT`), so the same IP shows the same value but cannot be recovered. The admin page has a 「登录记录」 tab that filters by account (name or id; for unknown names the typed name is matched) and by kind (`GET /api/admin/authlog?q=&act=`). Writing the log never blocks a sign-in. **Needs a Worker redeploy.**
- **Signed-in devices (`cloudflare/worker.js`, `src/cloud.js`, `src/game/24-account.js`, `src/page.html`)**: the account page lists the devices signed in to this account (system and browser only, e.g. 「iPhone · Safari」, and when each was last used; `last_seen` is written at most every 5 minutes). Each one can be signed out, and 「所有设备都退出」 signs out every device including this one. A device that is signed out loses its token and refresh token at once, so its next request gets 401. Sign-ins from before the refresh-token change are shown as one 「以前的登录」 entry and can be signed out together. API: `GET /api/devices`, `POST /api/devices` with `{id}`, `{id: 'legacy'}` or `{all: true}`. **Needs a Worker redeploy.**
- **Short-lived tokens with rotating refresh tokens (`cloudflare/worker.js`, `src/cloud.js`, `cloudflare/schema.sql`)**: when the `auth.refresh` flag is on for the account, sign-in returns a 30-minute token plus a refresh token. Each browser is one row in a new `devices` table (refresh stored only as a hash); `POST /api/refresh` swaps the refresh token for a new pair and retires the old one in `refresh_used`. A retired refresh token used again ends that device's whole session group (its refresh and every token it issued), so a stolen one stops working for everyone and the owner signs in again. Two tabs refreshing at once are not treated as theft: within one minute the server answers 409 and the page picks up the pair the other tab stored (tabs also queue with `navigator.locks` where available). The page refreshes two minutes before expiry and once on a 401, then retries the request; when refreshing fails the sync state becomes 「登录过期」 and unsent progress waits on this device. Old 30-day tokens are exchanged on the next page load without signing in. Pages that do not send `rt: 1` (cached old pages) and accounts without the flag keep getting 30-day tokens. Logout and an admin password reset also end the device groups. The flag defaults to the Dev account only. **Needs a Worker redeploy.** Tests in `tools/econ-test.mjs` and `tools/sync-test.mjs`.
- **Server feature flags (`cloudflare/worker.js`, `cloudflare/admin.html`, `src/cloud.js`)**: big changes can ship behind a switch. Flags are registered in `FLAGS` in the Worker (`[default, description, page needs it]`); only changed values are stored, in a new `flags` table (created by `ensureSchema`). The admin page has a 「功能开关」 tab: each flag can be off, on for the Dev account only, or on for everyone; every change needs a reason and is in the audit log. Pages read `GET /api/flags` on load and on sign-in/out (60 per IP per minute) and see only the flags marked for the page; `CloudSave.flag(name)` returns true/false and keeps the last known value per account when offline. No flags are registered yet, so nothing changes until one is added. **Needs a Worker redeploy.** Tests in `tools/econ-test.mjs` and `tools/cloud-test.mjs`.
- **Open world co-op (`src/game/22-world.js`, `cloudflare/worker.js`, `cloudflare/wrangler.toml`)**: a new 「江湖共斗 · 开放世界」 entry in the 同袍肉鸽 dialog. Everyone shares one 8000-wide map in four zones (竹林, 古道, 山寨, 魔窟, harder further in), can join or leave at any time, and sees the other players nearby with their names and health. Monsters and the world boss (妖王, appears after every 40 kills on a line, health scales with players online, shared health bar) run on the server; each browser simulates only its own hero, so controls feel like single player. A line holds 40 players; when it is full the game moves to the next line, so there is no total limit. Players can type a line number to join a friend. Each player only receives the players and monsters within 2000 px, and the server caps damage per hit and per second. Falling respawns you at the zone's 土地庙 after 3 seconds. Not in the offline build. **Needs a Worker redeploy** (adds the `WORLD` Durable Object binding; works on the free plan). Tests: `node tools/world-test.mjs`.
- **Keyboard-only play, issue #4 (`src/game/26-kbnav.js`)**: every menu, dialog, the ban/pick screen, pause, settings, results, story choices and tower scrolls work without a mouse. Arrow keys or WASD move a gold selection frame by screen position, Enter / Space press the selected item, Esc closes the dialog or goes back, Tab walks in order. Clicking or touching hides the frame; mouse and touch work as before. On the ban/pick screen, Enter on a card selects it and Enter again confirms. 1P gets a keyboard attack key, `X` by default (hold to charge), rebindable in settings; no other player's layout uses it.
- **Multiplayer roguelike raid mode 同袍肉鸽 · 众志破魔 (`src/game/22-modes.js`, `src/page.html`, `src/game/08-fighter-match.js`)**: added a dedicated co-op raid battle mode on the main home screen supporting 2–3 players with shared team roguelike scrolls (秘卷) and shared healing qi against a fused-soul Raid Boss (融魂魔首) wielding 6 active skills randomized from 3 heroes, 300% HP, and 125% damage; supports local keyboard play, online lobby matchmaking, and private room sharing.
- **Hero story routes 侠客列传 (`src/game/07-ai-story.js`, `src/page.html`)**: added narrative story routes for all 13 playable heroes in the monster-fighting / roguelike co-op mode, complete with character-specific backstories, locations, stage titles, contextual wave dialogue, and custom boss encounter intros.
- **AI Trainer simulation harness (`tools/trainer.mjs`)**: introduced a headless AI-vs-AI combat simulation harness to benchmark matchup win rates across all hero pairings and difficulty levels, generating data-driven balance proposals with fresh-seed verification.

### Changed

- **CORS limited to the game page (`cloudflare/worker.js`, `docs/admin.md`)**: the Worker no longer answers `Access-Control-Allow-Origin: *`. Browsers may call the API only from `https://amfi-disable.github.io` and from local development (`localhost`, `127.0.0.1`, `[::1]`, any port); more origins can be added with the Worker variable `CORS_ORIGINS` (comma-separated). The allowed origin is echoed back with `Vary: Origin`, also on errors. Other sites, look-alike hosts and `null` (the offline build, which does not use the server) get no CORS headers. Requests without an `Origin` (command line, curl) work as before. `/api/admin/*` never sends CORS headers and answers 403 to any request whose `Origin` is not the Worker itself, so only the Worker's own `/admin` page and `tools/econ-admin.mjs` can use it. **Needs a Worker redeploy.**
- **Passwords use PBKDF2 (`cloudflare/worker.js`, `cloudflare/schema.sql`, `docs/admin.md`)**: new and admin-set passwords are stored as PBKDF2-SHA256 with 25000 iterations (`PW_ITER`), with a new 16-byte salt. Two columns are added to `users`: `password_algo` (`pbkdf2-sha256:<iterations>`, or `sha256-v1` for the old single SHA-256) and `password_updated_at`; existing databases get them automatically on the first request. Old accounts keep their password: after the next successful login it is re-hashed with PBKDF2, without signing other devices out. The iteration count was measured against the free plan's 10 ms CPU limit (workerd: 10k 1.7 ms, 20k 2.9 ms, 30k 4.1 ms, 50k 6.7 ms, 100k 12.8 ms; the rest of a login is under 1 ms), so 25000 takes about 3 ms. Behind the `auth.pbkdf2` flag (default on); turning it off only makes new passwords use the old method, and both kinds keep working. **Needs a Worker redeploy.**
- **Session tokens are stored hashed (`cloudflare/worker.js`, `cloudflare/schema.sql`)**: the `sessions` table keeps `h1:` + SHA-256 of each token instead of the token itself, so a copy of the database contains no usable login. Tokens stored in plain text before this change still work; the first time one is used it is rewritten to its hash (same expiry), so nobody has to sign in again. A plain token must be 64 hex characters, so a stored hash cannot be replayed as a token. HTTP requests, logout and the open world's login check all go through the same lookup. Behind the `auth.token_hash` flag (default on); turning it off only makes new tokens plain again, and both kinds keep working either way. **Needs a Worker redeploy.**
- **Public redeem codes revoked (`cloudflare/worker.js`, `src/game/19-progress.js`, `src/armory.js`)**: the five codes written in the source (`ZODIAC2026STAR`, `RENYING666`, `RENYING888`, `SWORD2026`, `MOYUGIFT`) are void: entering one shows "该兑换码已作废" and grants nothing, and the server no longer accepts `ZODIAC2026STAR`. What was already granted by the zodiac code is taken back once per account: on cloud accounts that have a `code_got` record for it, items with `src: 'code'` from the zodiac case are removed from the inventory and any still-open market listing of them is withdrawn (logged as `code_void`, done once, marked in `srv.zv`); copies already bought by other players are left with the buyers. Local accounts drop those items on load, and guests lose the zodiac skins the code added. Items from the zodiac case itself and from admin-created codes are not touched. Ink already granted by the four ink codes is not taken back: it was mixed into balances and never reported to the server. Audit item ECO-01. **Needs a Worker redeploy.**
- **2v2 is two players per team (`src/game/22-modes.js`, `src/page.html`)**: the formats are two players vs two computers and two players vs two players; the player + computer teammate format is removed. 2v2 has one entry, the 2v2 card on the battle page (the single-player page in the offline build), which opens one dialog: pick the format, then same computer, server matchmaking or a friend room. The separate 2v2 page in single-player mode is gone. Spectating four AIs stays as a link in the dialog. Gameplay, hero stats and balance are unchanged.
- **3v3 tag wheel multiplayer relay (`src/game/08-fighter-match.js`, `src/game/23-demo-cards.js`)**: online rooms, matchmaking, and ranked play expanded to full 3v3 tag wheel relay matches (先锋, 中坚, 大将) using snake drafting (`BP_TAG3_STEPS`); defeated fighters swap in the next hero at full HP while round winners carry over remaining health with carry heal (`CARRY_HEAL`).
- **Dev is a normal account (`src/cloud.js`, `src/anticheat.js`, `src/game/19-progress.js`, `src/armory.js`, `cloudflare/worker.js`)**: Dev no longer gets all heroes, all skins, 1,000,000 ink and a filled armory on login, no longer falls back to a local `dev_master` account offline, and is no longer exempt from anti-cheat. The developer redeem code that turned any session into Dev and the session-wide unlock are removed. On the server, saves from the Dev account go through the same ledger and armory checks as everyone else; before, its ink, skins and armory inventory were taken from the browser as sent, so a local edit overwrote the cloud account. Existing cloud data is kept as it is. A device still signed in as the old local `dev_master` is signed out once; its local save is left in place. The admin panel button stays visible on the cloud Dev account. **Needs a Worker redeploy.**
- **Bound skins become armory items (`cloudflare/worker.js`, `src/armory.js`)**: skins that were never in the armory inventory (stage rewards, skins carried over from old local accounts) were shown as "绑定账号，不能出售和汰换". Accounts created before 2026-10-31 get each of them converted once into a regular armory item the first time the armory syncs, so they can be listed on the player market and used in trade-ups; selling the last copy removes the skin like any other item. The conversion is logged as `legacy`. Local accounts convert on load. Skins reported by the browser after that, and on accounts created later, stay bound, because the server cannot verify them.
- **Lingque hero balance tuning (`src/game/02-heroes.js`, `src/game/03-skills.js`, `src/game/04-ults.js`)**: tuned Lingque's damage and mobility (damage multiplier 1.02 -> 0.96, walk speed 1.15 -> 1.10, guard max 95 -> 92, escape cooldown 8.0s -> 8.5s); reduced needlemark (雀芒) duration from 4.0s to 3.5s; decreased spindle (穿叶飞梭) damage from 38 to 30, projectile velocity from 1150 to 1050, and max hits from 3 to 2; reduced shadowdash (移形换影) damage from 42 to 34 (mark detonation damage from 52 to 38) and tuned tracking turn speed; and reduced needlestorm (万线归宗) finisher damage from 76 to 56.
- **Lingque's R (移形换影) homes in (`src/game/03-skills.js`)**: after the wind-up she flies at 1520 px/s and turns toward the target every frame (up to 14 rad/s) for up to 0.8 s, catching targets that dash, jump, or maneuver behind her; while the target is invulnerable (腾空闪 and similar dodges) she stops steering and flies straight.
- **Gouchen hook range extension (`src/game/03-skills.js`)**: extended chain hammer hook (飞锤) projectile lifetime from 0.28s to 0.33s (increasing effective reach from ~420px to ~495px) and aligned AI engagement distance to 160–500px.

### Fixed

- **Several tabs of the same browser stay on the same account (`src/cloud.js`, `src/game/24-account.js`)**: signing in, switching account or signing out in one tab is passed to the others with `BroadcastChannel` (the `storage` event where it is missing). The other tabs drop their in-memory account and unsent save, so a tab that still had the old account in memory can no longer upload that account's progress into the newly signed-in one (a sync also checks the stored account first). The game then reloads the page once the player is back in a menu, never in the middle of a match. 401 and 403 now go through one place: a 401 after a failed refresh marks the sync as 「登录过期」 and keeps progress on the device, a 403 is reported as banned or forbidden, and the game shows each kind once (`CloudSave.onAuthError`, `CloudSave.onOtherTab`). Tests in `tools/sync-test.mjs`.
- **Progress from two devices overwrote each other instead of adding up (`src/cloud.js`, `cloudflare/worker.js`, `src/game/24-account.js`, `tools/sync-test.mjs`)**: the server stored whatever profile arrived last, so wins, losses and hero fragments earned on one device were lost when another device uploaded, and stage stars, heroes and story progress from the earlier upload disappeared. Wins, losses and fragments now use the same idea as the ink ledger: each save records "how much changed since the last save" as an entry with an id, the server adds each id once, and the absolute numbers in the save are ignored. Two devices' new progress is summed, and retries, lost replies, reloads, re-login and reconnects never count an entry twice. When an upload reveals progress made on another device, it is added to the running profile instead of overwriting local changes. Stage stars and the 青锋行 best (best scores) keep the higher value per item, heroes are a union, story progress keeps the further route per hero, ranked state keeps the newer copy, all merged on the server. The first load on the new version has no baseline, so it only adds what the local copy has above the cloud (never subtracts, never adds twice); every load after that is incremental. Older pages and an older Worker keep the previous behaviour until both are updated. Bug-status item O4. **Needs a Worker redeploy.**
- **Leaderboard always showed "读取失败" (`cloudflare/worker.js`, `src/cloud.js`, `src/game/24-account.js`)**: both tabs requested `/api/ranklb` and `/api/leaderboard` from the site the page was served from (GitHub Pages), which has no such API. The Worker now serves `GET /api/leaderboard`: the rank tab lists this season's players who finished placement, by rank points (clamped to 1,000–25,000), and the record tab lists online wins and losses; banned accounts are left out, 30 requests a minute per IP. The numbers come from players' own saves and are for display only. The stale `renying-token` key is deleted on load and no longer written. **Needs a Worker redeploy.**
- **Sign-up and sign-in fallbacks were silent (`src/cloud.js`, `src/game/24-account.js`, `src/game/19-progress.js`)**: when the server could not be reached or answered 500, sign-up quietly created a local account and said "注册成功，已开启专属存档". It still creates the local account, but now says it is only on this device and can be upgraded later; signing in to a local account says so too, including when a cloud account with the same name has a different password. A corrupted local account table no longer makes sign-up throw a JSON error, local nicknames are no longer case-sensitive (like the server), and reserved nicknames are refused before a local account is made. Audit items B1, B2, B4, A5, B7.
- **`guest` and `游客` could be registered (`cloudflare/worker.js`, `src/cloud.js`)**: signed-out progress, tasks and claim records are kept under that name, so such an account shared them with every signed-out player on the device. Both names are now reserved. Existing accounts with those names still sign in. Audit item A2. **Needs a Worker redeploy.**
- **Importing a backup failed after it had already switched account (`src/cloud.js`, `src/game/24-account.js`)**: the import screen read `res.profile.ink` from a value that was the profile itself, so a successful import showed an error and the profile was only applied after a reload. Import now returns the account and profile, says that it switched to that local account, and shows the note for old backups that only signed six fields. A bare profile file, which the screen says it accepts, is accepted. Bug-status items O1 and O3.
- **AI difficulty carried over to the next account (`src/game/24-account.js`)**: signing in did not reload the adaptive difficulty, so the previous player's tuning was kept and saved under the new account. Audit item A7.
- **Legacy shared cache deleted while signed out (`src/cloud.js`)**: the one-time migration of `renying-cloud-cache` now leaves the key alone when nobody is signed in instead of deleting it unclaimed. Audit item D5.
- **Online count stayed at 1 when more people were playing (`src/game/24-account.js`, `src/social.js`)**: the number was `Math.max(1, …)`, so whenever this tab's own heartbeat reply was missing or stale it printed "1 人在线" no matter how many were really on. The count is now the larger of the cloud presence table and the hall roster, shows "—" when neither is known, refreshes the moment the hall roster changes (who joins or leaves is broadcast instantly over the peer connection), beats immediately on focus, tab restore and game-state change, polls every 3 s for 30 s after the count moves and every 10 s while the hall is unreachable, rotates its session id when the cloud answers "sid 不对" (which happens after a network or IP change and used to silence the tab forever), and can no longer be stalled by one hung request. Players in a match stay in the hall roster instead of dropping out for the whole fight.
- **Text was never translated (`src/i18n.js`)**: `translateNode` read `node.datasetOrigText` on text nodes, which have no `dataset`, so the first text node threw a `TypeError` — English mode did nothing and `chooseLang` never reached the menu. The original text is now kept as a node property, and switching language works.
- **Dynamic UI translation coverage and missing strings (`src/i18n.js`)**: added a `MutationObserver` on `document.body` to automatically translate dynamically injected DOM elements and modal screens after switching language; added regex pattern translation for numbered strings (`全服 N 人在线`, `剩余 N 天`); and added dictionary translations for ~90 previously unmapped panel headings, buttons, and task labels.
- **Armory skins disappearing after a refresh (`src/armory.js`, `src/game/19-progress.js`, `cloudflare/worker.js`)**: the zodiac code added its skins in the browser only, and a hack kept them in the skin list after the server dropped them (and after they were sold). - **Last save lost when closing the tab (`src/cloud.js`)**: the debounced save flushed on `pagehide` / tab hide is now sent with `keepalive`, so the browser no longer cancels it as the page closes.
- **Expired login silently stopped cloud saves (`src/cloud.js`, `src/game/24-account.js`, `src/game/17-home.js`)**: a 401 used to be treated as a refused save, which cleared the pending marker. It now shows "登录已过期" and keeps the marker; logging back in keeps the local mirror instead of overwriting it with the server copy, so the unsynced progress is merged and uploaded. The "blocked" and "expired" sync states now have labels in the account panel and top bar.

It now compares the whole progress and checks the ink ledger for unreported entries.
- **Local account upgrade ink retention (`src/cloud.js`, `src/game/24-account.js`)**: registering a cloud account from a local guest profile now attaches the local save data with the registration request, allowing ink balances up to `REG_INK_CAP` (5,000 ink) to carry over properly rather than reverting to starting ink.
- **Guest session state cleared on page reload (`src/cloud.js`, `src/game/19-progress.js`, `src/game/24-account.js`)**: `loadProfile()` now explicitly marks loaded guest blobs with `guest: true` and derives the guest state from `CloudSave.getUser()`, ensuring login-only tasks and compensation rewards remain properly gated for unauthenticated visitors.

## [1.0.0] - 2026-10-26

Release pass for issue #11. Only changes that were implemented and then checked are listed: the repository suites (`build.py --check`, combat `--sim`, rollback, economy, economy `--bundle`, cloud) pass, plus browser regression scripts for each item below. **The Worker has to be redeployed** for the online count, global boss, story footprints and the zodiac code fix.

### Added

- **Aerial Q / R and air attacks (`src/game/01-core.js`, `src/game/02-heroes.js`, `src/game/09-actions.js`, `src/game/11-anim-loop.js`)**: every hero can use Q and R in the air. Damage, hitboxes and cooldowns are the same as on the ground; the hero switches to an air-only pose (`AIR_SKILL_POSE`) and falls slower while a ground skill plays, like an air attack. Air light attacks (`a1` / `a2`) have their own pose set for each of the 13 weapons.
- **Global boss raid 天魔讨伐 (`src/game/22-tianmo.js`, `cloudflare/worker.js`)**: every player fights the same server-side boss. Terminal offers never go below the market price, and a case's expected value is below its price. Under these spreads, buying on any day and selling on any later day, trading up items bought on the market, or reselling terminal items always loses ink. `tools/econ-test.mjs` checks the worst case from the rules and also replays a year of market listings and trade-ups.
- **Server-Authoritative Armory Economy & Ink Ledger (`cloudflare/worker.js`, `src/cloud.js`, `src/anticheat.js`, `tools/econ-admin.mjs`, `tools/econ-test.mjs`)**:
  - Every armory action (open, buy case, terminal, buy, sell, list, trade-up, equip) is computed by the Worker; the client only shows the result. Writes are version-checked and retried, and every request carries a nonce, so replayed and concurrent requests (double-spends) apply once.
  - The weekly limit of 5 cases, terminal offers (which one is showing, and buying it at most once) and 斩数 counts are enforced on the server. A 斩数 count only grows from a match with a server ticket and a minimum length, by at most 12 KOs across at most 3 heroes, and only for an equipped 斩数 item.

Local income per day is capped at 1,500 plus 80 per server-verified match (6,000 at most); small overflow is queued (4,000 at most) and paid out later. Spending always applies and can't be voided. Reports of tens of thousands at once are logged for the admin.
  - When the client anti-cheat catches a forged ink jump it voids exactly the forged ledger entries and checks the balance right before every upload, so legitimate balance is never wiped; if an entry already reached the server, the server takes back exactly what it credited for it.
  - Uploaded profiles can't add armory skins; registration caps carried-over ink at 5,000. Strikes (warning, 24 h ban, permanent ban) are enforced on the server and block trading and syncing.
